# テーマ / アイデア機能

「成果物になったものしか可視化できない」状態からの脱却を目的とした機能です。

- いま誰が何に着手していて、どこまで進んでいるかを抽出できる
- 同じことを別々にやっている人を合流（チーム化）させ、重複開発を防ぐ
- 「アイデアはあるが自分では作れない」層の受け皿を用意する
- 完走しなかった取り組み（凍結）も、理由とセットで知見として残す

## 全体像

```
アイデア（困りごと）  ──「着手する」──▶  テーマ  ──▶  進捗の積み重ね  ──▶  完了 ──▶ ツールカタログ
   賛同(▲)で需要を測る         手を挙げた人が発起人        （軌跡）          │
                                   ▲                                        └──▶ 凍結（理由必須）
                                   │
                            合流申請 → 承認 でチーム化
                            重複テーマは「統合」で1本化
```

## 画面

| URL | 内容 |
| --- | --- |
| `/themes` | テーマ一覧。状態・停滞・自分の でフィルタ、検索 |
| `/themes/new` | テーマ登録。**入力中に似たテーマを提示**（重複開発の抑止） |
| `/themes/:id` | 詳細。軌跡（タイムライン）、メンバー、参加申請、凍結・統合 |
| `/themes/:id/edit` | 編集 |
| `/ideas` | アイデア一覧。賛同順 |
| `/ideas/:id` | 詳細。賛同・コメント・「これに着手する」 |
| `/admin/dashboard` | 進行中テーマの集計と、凍結理由のダイジェスト |

ヘッダーの「🚀 テーマ」から入れます。

## 状態（ステータス）

| 状態 | 意味 |
| --- | --- |
| 🙋 仲間募集中 | やりたいが人手・スキルが足りない |
| 🚀 着手中 | すでに手を動かしている |
| 🧊 凍結 | 課題により中断。**理由が必須** |
| ✅ 完了 | 成果物が出た。ツールカタログと相互リンク |
| 🔗 統合済み | 別テーマに合流した。中身は合流先にある |

### 「停滞」は状態ではありません

**停滞はデータとして保存していません。**「最終進捗からの経過日数」から
その場で計算する派生値です。こうしている理由は2つあります。

1. 放置しただけで勝手にデータが書き換わらない（バッチ処理も不要）
2. しきい値を変えると、過去のテーマも含めて表示が即座に追従する

しきい値は既定30日で、`.env` の `THEME_STALLED_AFTER_DAYS` で変更できます。

```
THEME_STALLED_AFTER_DAYS=30
```

凍結・完了・統合済みは停滞の対象外です。止まっているのが正常な状態なので、
停滞として数えるとノイズになります。

## 重複開発をどう防ぐか

2段構えです。

1. **登録前に気づかせる** — `/themes/new` でテーマ名を入力すると、
   タイトルの語・タグ・業務カテゴリの重なりでスコアリングして
   似たテーマを最大5件出します。そのままリンクで飛んで合流できます。
2. **後から1本化する** — すでに重複してしまったら「統合」します。

### 合流（参加申請）

非メンバーが「このテーマに合流する」→ 発起人が承認 → メンバーになります。
メンバーになると**進捗を書けるようになります**。

コメントはメンバーでなくても書けます。外からの助言や
「それ自分もやっています」を拾うためです。

### 統合（テーマの1本化）

**自分のテーマを相手のテーマに合流させる**操作です。吸収される側の発起人が
実行するので、相手側の承認は要りません（自分の持ち物を差し出す操作のため）。

統合すると:

- 吸収される側のメンバーは、合流先のメンバーになる
- 進捗の記録（軌跡）は合流先へ移送される
- 吸収された側は「統合済み」になり、合流先へのリンクだけが残る

## 軌跡（タイムライン）

進捗・コメント・システム記録を**1本の時系列**にまとめています。
ステータス変更や合流も同じ流れに残るので、「どんな経緯でここまで来たか」が
1画面で読めます。

| 種別 | 誰が書けるか |
| --- | --- |
| 📈 進捗 | メンバーのみ。進捗率(0-100%)を任意で付けられる |
| 💬 コメント | ログインユーザー全員 |
| 記録 | システムが自動生成（編集・削除不可） |

進捗には**投稿時点のステータス**が記録されます。後から振り返ったときに
「これは凍結前に書かれたものだ」といった文脈が失われないようにするためです。

## 凍結を「成果」として扱う

凍結には**理由の入力が必須**です。何が課題で止めたのかは、それ自体が
部門の知見になるためです。理由はダッシュボードに一覧表示されます。

再開しても `freeze_reason` は消しません。一度止まった事実と理由は
残す価値があります。

## API

| メソッド | パス | 用途 |
| --- | --- | --- |
| GET/POST | `/api/themes/` | 一覧・登録（`status` `q` `tag` `category` `mine` `stalled` で絞込） |
| GET/PATCH/DELETE | `/api/themes/{id}/` | 詳細・更新・削除 |
| GET | `/api/themes/similar/` | 重複チェック（`title` `tags` `categories` `exclude`） |
| GET | `/api/themes/summary/` | 集計（状態別件数・停滞数・凍結理由） |
| GET/POST | `/api/themes/{id}/entries/` | 軌跡の取得・投稿 |
| PATCH/DELETE | `/api/theme-entries/{id}/` | 記録の編集・削除 |
| POST | `/api/themes/{id}/join/` | 合流申請 |
| GET | `/api/themes/{id}/join-requests/` | 申請一覧（発起人のみ） |
| POST | `/api/themes/{id}/join-requests/{rid}/resolve/` | 承認・却下 |
| POST | `/api/themes/{id}/leave/` | 離脱 |
| POST | `/api/themes/{id}/freeze/` | 凍結（`reason` 必須） |
| POST | `/api/themes/{id}/reopen/` | 再開 |
| POST | `/api/themes/{id}/merge/` | 統合（`target`） |
| GET/POST | `/api/ideas/` | アイデア一覧・投稿 |
| POST | `/api/ideas/{id}/vote/` | 賛同トグル |
| GET/POST | `/api/ideas/{id}/comments/` | コメント |
| POST | `/api/ideas/{id}/promote/` | テーマ化 |

## 権限

| 操作 | 誰が |
| --- | --- |
| 閲覧 | ログインユーザー全員 |
| テーマ登録・アイデア投稿 | 全員 |
| 進捗の投稿 | メンバー（＋管理者） |
| コメント | 全員 |
| テーマの編集・凍結・統合・申請承認 | 発起人（＋管理者） |

## サンプルデータ

```
python manage.py seed_themes          # 冪等
python manage.py seed_themes --reset  # 作り直す
```

着手中・仲間募集中・停滞・凍結・完了が一通り揃うので、一覧のフィルタと
ダッシュボードの集計をすぐ確認できます。

## 実装メモ

- フロントのストアは **Context 必須**（`ThemeProvider` / `useThemeStore`）。
  状態を作るフックを複数コンポーネントから呼ぶと別インスタンスになり、
  同期しなくなる。このリポジトリでは docs / forum で3回踏んでいる。
- 一覧APIは `members` / `entries` を返さない。`mergeThemeList()` で
  詳細取得済みの値を保護している（フォーラムで「>>1 しか出ない」として
  踏んだのと同じ罠）。
- ヘッダーのナビ項目を増やしたら、`.header-nav .nav-label` を畳む
  メディアクエリの閾値を実測で見直すこと。テーマ導線の追加時に
  1240px → 1440px へ引き上げた。
